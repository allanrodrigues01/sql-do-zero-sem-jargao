1. O que é SQL

Pense numa planilha de Excel. Ela tem colunas com títulos (nome, cidade, idade) e linhas com os dados de cada pessoa. Um banco de dados relacional é um conjunto de planilhas assim, guardadas num programa que aguenta milhões de linhas e vários usuários ao mesmo tempo.

SQL (Structured Query Language, “linguagem de consulta estruturada”) é o idioma que você usa para pedir coisas a esse banco: “me mostre”, “some”, “adicione”, “apague”. Funciona em PostgreSQL, MySQL, SQL Server, Oracle, SQLite e outros, com pequenas diferenças de dialeto.

Vocabulário mínimo

Uma diferença importante

Na planilha você clica e edita. No SQL você escreve o que quer e o banco decide como buscar. Você descreve o resultado, não o caminho.

2. Laboratório: prepare seus dados de treino

Todos os exemplos usam duas tabelas pequenas. Para praticar de verdade, crie-as num SQLite online (veja a seção 13): cole o script abaixo e execute. Depois rode cada exemplo da página e compare com o resultado mostrado.

3. SELECT: consultar dados

SELECT significa “mostre”. FROM diz de qual tabela. É o comando que você mais vai usar.

SELECT nome, cidade
FROM clientes;

Para trazer todas as colunas, use o asterisco:

SELECT * FROM clientes;

Apelidos e valores repetidos

-- AS dá um apelido à coluna no resultado
SELECT nome AS cliente, idade AS anos
FROM clientes;

-- DISTINCT remove repetições
SELECT DISTINCT cidade
FROM clientes;
Regras de escrita

O ponto e vírgula (;) encerra o comando. Maiúsculas e minúsculas nos comandos não fazem diferença, mas escrever SELECT em maiúsculas ajuda a ler. Linhas que começam com -- são comentários e o banco ignora.

4. WHERE: filtrar linhas

WHERE significa “somente onde”. Ele escolhe quais linhas aparecem.

SELECT nome, cidade
FROM clientes
WHERE cidade = 'São Paulo';
Texto vai entre aspas simples

Use 'São Paulo', nunca aspas duplas. Números ficam sem aspas: idade = 30.

Os operadores mais usados

OperadorSignificaExemplo

ANDas duas condições juntasidade >= 18 AND cidade = 'Recife'

SELECT nome, idade
FROM clientes
WHERE idade BETWEEN 25 AND 35;

No LIKE, o % vale por “qualquer coisa”. 'A%' é “começa com A”, '%a' é “termina com a”, '%li%' é “contém li”.

O vazio se chama NULL

NULL significa “sem valor / desconhecido”. Ele não é zero nem texto vazio. Por isso cidade = NULL nunca funciona; o correto é cidade IS NULL ou IS NOT NULL.

5. ORDER BY e LIMIT: ordenar e limitar

SELECT nome, idade
FROM clientes
WHERE idade >= 30
ORDER BY idade DESC;
  • ASC é crescente (o padrão); DESC é decrescente.
  • Dá para ordenar por mais de uma coluna: ORDER BY cidade, idade DESC.

Para pegar só as primeiras linhas, use LIMIT:

SELECT nome, idade
FROM clientes
ORDER BY idade DESC
LIMIT 2;
Dialetos

O LIMIT 2 funciona em PostgreSQL, MySQL e SQLite. No SQL Server, escreve-se SELECT TOP 2 nome, idade .... O resto da linguagem é quase igual em todos.

6. Contar, somar e agrupar

Funções de agregação transformam várias linhas em um número só:

FunçãoFaz
COUNT(*)conta linhas
SUM(coluna)soma
AVG(coluna)média
MIN(coluna) / MAX(coluna)menor / maior valor
SELECT COUNT(*) AS total,
       AVG(idade) AS idade_media,
       MAX(idade) AS mais_velho
FROM clientes;

GROUP BY: um resumo por grupo

GROUP BY separa as linhas em grupos e aplica a função em cada um. Aqui, um total por produto:

SELECT produto,
       COUNT(*)   AS qtd,
       SUM(valor) AS total
FROM pedidos
GROUP BY produto;

HAVING: filtrar depois de agrupar

SELECT produto, SUM(valor) AS total
FROM pedidos
GROUP BY produto
HAVING SUM(valor) > 150;
WHERE ou HAVING?

WHERE filtra as linhas antes de agrupar. HAVING filtra os grupos depois de somar ou contar. Se a condição usa SUM, COUNT etc., é HAVING.

7. JOIN: juntar tabelas

Bancos dividem os dados em várias tabelas para não repetir informação. Em vez de escrever o nome e a cidade da Ana em cada pedido dela, o pedido guarda só o cliente_id = 1. O JOIN é o que junta as duas de volta, casando o id do cliente com o cliente_id do pedido.

INNER JOIN: só quem tem correspondência

SELECT c.nome, p.produto, p.valor
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id;

c e p são apelidos das tabelas, para escrever menos. A cláusula ON diz qual coluna casa com qual.

LEFT JOIN: todos da esquerda, com ou sem correspondência

SELECT c.nome, p.produto, p.valor
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id;

Um truque útil: quem nunca comprou?

SELECT c.nome
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
WHERE p.id IS NULL;

Juntando com totais

SELECT c.nome, SUM(p.valor) AS total_gasto
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id
GROUP BY c.nome;
Regra prática

Quer só o que existe nas duas tabelas? INNER JOIN. Quer manter todos de uma tabela mesmo sem correspondência? LEFT JOIN dessa tabela.

8. Inserir, atualizar e apagar

Até aqui só lemos dados. Estes três comandos alteram o banco.

-- Inserir uma linha nova
INSERT INTO clientes (id, nome, cidade, idade)
VALUES (7, 'Gustavo', 'Salvador', 28);

-- Atualizar linhas existentes
UPDATE clientes
SET cidade = 'Olinda'
WHERE id = 5;

-- Apagar linhas
DELETE FROM pedidos
WHERE id = 102;
Sem WHERE, vale para a tabela inteira

UPDATE clientes SET cidade = 'Olinda'; muda a cidade de todos os clientes. DELETE FROM pedidos; apaga todos os pedidos. Não há botão de desfazer por padrão.

Hábitos que evitam desastres

  1. Escreva primeiro um SELECT com o mesmo WHERE e confira quais linhas aparecem.
  2. Só então troque o SELECT por UPDATE ou DELETE.
  3. Em bancos de trabalho, faça backup antes e peça a alguém experiente para revisar.
  4. Se o seu banco permite, use transações: BEGIN; abre, ROLLBACK; desfaz, COMMIT; confirma.

Se você executar esses exemplos no laboratório, seus dados vão diferir dos das seções anteriores. Basta recriar as tabelas com o script da seção 2.

9. Criar tabelas

CREATE TABLE pedidos (
  id         INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL,
  produto    VARCHAR(50) NOT NULL,
  valor      DECIMAL(10,2) DEFAULT 0,
  FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

Cada linha dentro dos parênteses é uma coluna: nome, tipo e, se quiser, regras.

Tipos mais comuns

TipoGuarda
INTEGERnúmeros inteiros
DECIMAL(10,2)números com casas decimais (dinheiro): até 10 dígitos, 2 depois da vírgula
VARCHAR(n) / TEXTtexto
DATEdatas
BOOLEANverdadeiro ou falso

Regras (constraints)

  • PRIMARY KEY: identifica cada linha de forma única, sem repetição.
  • NOT NULL: a coluna não pode ficar vazia.
  • UNIQUE: não permite valores repetidos (ex.: e-mail).
  • DEFAULT: valor usado quando você não informa nenhum.
  • FOREIGN KEY (chave estrangeira): garante que cliente_id aponte para um cliente que existe.

Para mudar ou remover depois: ALTER TABLE (alterar a estrutura) e DROP TABLE (apagar a tabela inteira, com cuidado).

10. Erros comuns de iniciante

  • Aspas erradas. Texto usa aspas simples: 'Recife'.
  • Esquecer o WHERE em UPDATE e DELETE.
  • Comparar com NULL usando =. Use IS NULL.
  • Coluna solta no GROUP BY. Todo campo do SELECT que não é função de agregação precisa estar no GROUP BY.
  • Vírgula sobrando ou faltando na lista de colunas. A última coluna não leva vírgula.
  • Confundir WHERE com HAVING. Veja a seção 6.
  • Escrever na ordem errada. A ordem é fixa:
SELECT   colunas
FROM     tabela
JOIN     outra_tabela ON ...
WHERE    filtro_de_linhas
GROUP BY grupos
HAVING   filtro_de_grupos
ORDER BY ordenacao
LIMIT    quantidade;

Ler a mensagem de erro ajuda mais do que parece: quase sempre ela aponta a linha ou a palavra onde o banco se perdeu.

11. Exercícios

Tente resolver cada um no laboratório antes de abrir a resposta. Errar e corrigir é onde o aprendizado acontece.

1. Mostre o nome e a idade de todos os clientes. fácil 
SELECT nome, idade
FROM clientes;
2. Mostre todas as colunas dos clientes de Curitiba. fácil 
SELECT *
FROM clientes
WHERE cidade = 'Curitiba';
3. Liste nome e idade de quem tem mais de 30 anos, do mais novo para o mais velho. fácil 
SELECT nome, idade
FROM clientes
WHERE idade > 30
ORDER BY idade ASC;
4. Quantos pedidos existem? fácil 
SELECT COUNT(*) AS total_pedidos
FROM pedidos;
5. Qual o cliente mais velho? médio 
SELECT nome, idade
FROM clientes
ORDER BY idade DESC
LIMIT 1;
6. Mostre o total gasto por cliente (nome e soma). médio 
SELECT c.nome, SUM(p.valor) AS total
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id
GROUP BY c.nome;
7. Quais clientes nunca fizeram pedido? médio 
SELECT c.nome
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
WHERE p.id IS NULL;
8. Desafio: quais clientes gastaram mais de 150 no total? desafio 
SELECT c.nome, SUM(p.valor) AS total
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id
GROUP BY c.nome
HAVING SUM(p.valor) > 150;

12. Folha de cola e glossário

-- CONSULTAR
SELECT col1, col2 FROM tabela;
SELECT DISTINCT col FROM tabela;
SELECT * FROM tabela WHERE col = 'texto' AND num > 10;
SELECT * FROM tabela ORDER BY col DESC LIMIT 5;

-- RESUMIR
SELECT COUNT(*), SUM(col), AVG(col), MIN(col), MAX(col) FROM tabela;
SELECT grupo, COUNT(*) FROM tabela GROUP BY grupo HAVING COUNT(*) > 1;

-- JUNTAR
SELECT a.col, b.col
FROM a INNER JOIN b ON b.a_id = a.id;   -- só correspondências
FROM a LEFT JOIN  b ON b.a_id = a.id;   -- todos de a

-- ALTERAR (sempre com WHERE!)
INSERT INTO tabela (col1, col2) VALUES ('x', 1);
UPDATE tabela SET col1 = 'y' WHERE id = 1;
DELETE FROM tabela WHERE id = 1;

-- ESTRUTURA
CREATE TABLE t (id INTEGER PRIMARY KEY, nome VARCHAR(50) NOT NULL);
ALTER TABLE t ADD COLUMN idade INTEGER;
DROP TABLE t;

Glossário

Banco de dados
Conjunto organizado de tabelas guardadas e gerenciadas por um programa (o SGBD).
SGBD
Sistema Gerenciador de Banco de Dados: PostgreSQL, MySQL, SQL Server, SQLite, Oracle.
Tabela, linha, coluna
A “aba”, um registro e um campo, respectivamente.
Chave primária (PK)
Coluna que identifica cada linha de forma única, como um CPF.
Chave estrangeira (FK)
Coluna que aponta para a chave primária de outra tabela, criando a ligação entre elas.
Consulta (query)
Qualquer comando SQL enviado ao banco, especialmente um SELECT.
Agregação
Transformar várias linhas em um resultado: contar, somar, tirar a média.
JOIN
Combinar linhas de duas tabelas a partir de uma coluna em comum.
NULL
Ausência de valor.
Transação
Grupo de comandos que só valem se todos derem certo; pode ser desfeito com ROLLBACK.

13. Como praticar e roteiro de estudo

Onde executar SQL sem instalar nada

  • SQLite Online (sqliteonline.com) e DB Fiddle (db-fiddle.com): cole o script da seção 2 e rode.
  • SQLBolt (sqlbolt.com): lições curtas e interativas, em inglês.
  • W3Schools SQL: cada exemplo tem um botão “Try it” que executa no navegador.
  • SQL Murder Mystery (mystery.knightlab.com): resolva um crime usando consultas. Divertido para fixar.
  • DB Browser for SQLite: programa gratuito para instalar no computador, quando quiser algo local.

Prefira SQLite para começar: não exige servidor nem configuração.

Roteiro em 4 semanas (20 a 30 minutos por dia)

  1. Semana 1: ler dados. Seções 1 a 5. Monte o laboratório e refaça cada exemplo digitando, sem copiar e colar. Exercícios 1 a 3.
  2. Semana 2: resumir dados. Seção 6. Invente perguntas sobre as tabelas (“qual a média por cidade?”) e responda com SQL. Exercícios 4 e 5.
  3. Semana 3: juntar tabelas. Seção 7, a que mais assusta e mais recompensa. Desenhe no papel qual coluna casa com qual antes de escrever o JOIN. Exercícios 6 a 8.
  4. Semana 4: alterar e criar. Seções 8 e 9, sempre num banco de treino. Depois monte um mini banco seu (livros, gastos do mês, coleção de filmes) e consulte-o.
Próximos passos

Quando isso estiver confortável, os assuntos seguintes são subconsultas (um SELECT dentro de outro), CASE WHEN (condições dentro da consulta), funções de data e texto, window functions e modelagem de bancos (como decidir quais tabelas criar).
